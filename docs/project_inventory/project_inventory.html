1. Dataset

REES46 "eCommerce behavior data from multi category store": anonymised clickstream of a large online marketplace, one row per event. Public, no account needed: https://data.rees46.com/datasets/marketplace/ (files 2019-Oct.csv.gz … 2020-Apr.csv.gz; also on Kaggle). Downloaded by scripts/00_download_data.py.

Cleaning rules (src/data/loader.py)

Duplicate rows dropped, null sessions dropped, price ≤ 0.0 dropped, sessions longer than 24 h dropped as logging artefacts, missing category/brand set to "unknown". Category labels harmonised across the December 2019 category-tree change (src/data/categories.py: each new category id takes the old label most of its products agree on, threshold 0.6).

Sessions, prefixes and target (src/data/sessionize.py)

Each session is cut after its first K ∈ [3, 5, 10] events. Only sessions with more than K events are kept, sessions that buy within the first K events are removed, and the target is target_purchase = 1 if a purchase happens after event K. Features use the first K events only, so nothing from the future leaks in.

Split (src/data/split.py)

Chronological by session start, 70% / 15% / 15% train / validation / test, no shuffling; sessions crossing a boundary are purged. At K=5: train 2019-10-01 → 2020-03-01, validation to 2020-04-04, test to 2020-04-30. The test weeks are never used for training, tuning, thresholds or calibration.

2. Features

Aggregated features of the K-event prefix for the tabular models (src/features/build_features.py), grouped for the ablation ladder (RQ3). Categorical: last_event_type, main_category, hour_of_day, day_of_week; top 20 categories kept, others → "other".

Sequences for the GRU/Transformer (src/features/sequences.py): per event, embedded event type (dim 4) and main category (dim 8), plus standardised log price and log gap since the previous event; exactly K steps, no padding.

Preprocessing (src/features/preprocessing.py), fitted on train only; log1p on heavy-tailed features (session_duration_sec, max_gap_sec, cart_to_view_ratio, price_mean, price_max, price_sum, price_std).

Training policy for every model: class weights "balanced" for the ≈10% buyers; early stopping on validation PR-AUC (LightGBM, MLP, TabNet, GRU, Transformer); decision threshold chosen to maximise F1 on validation; each model × K run with seeds [42, 7, 2026]; CPU only so latencies are comparable. Shared code: src/models/base.py (common interface and factory), src/models/torch_base.py (PyTorch training loop).
